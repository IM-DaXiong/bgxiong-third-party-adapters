## 0. 审核改稿结论

### 0.1 结论

原计划方向正确（单包三操作、以 ltx23 为模板、A2V 用官方 BF16 栈、默认提示词走 schema default），但按原文实施会出现 6 类必然失败：

1. A2V 的 `inputMode` 若写成任何新字符串，宿主装载即拒（宿主闭集没有 `audio_to_video`）。
2. A2V 无首帧时，ComfyUI 仍校验 `LoadImage` 文件，提交必报 `Invalid image file`。
3. A2V 图里的 Gemma API 编码节点是**自定义节点**，且残留 `ltx-2.3-22b-dev` 文件名，不剪掉就需要用户装额外节点包并备一个与本模式无关的 2.3 模型。
4. 官方 A2V 的提示词扩写默认是**开**，原计划写成「关」，会照搬出一个默认调用 LLM 扩写的模式。
5. T2V/I2V 的宽高节点是从 `ResolutionSelector` 连线来的，按 ltx23 只写 `inputs.value` 会把连线覆盖掉但不删除上游，A2V 的宽高则在第一阶段 latent 上、需写一半，原 `Mode` 结构表达不了。
6. F4/F5「只装一套权重时另一套模式单独报缺」与 ltx23 连通性探针的整包语义冲突。

本版对每一项给出冻结做法，并补齐文件清单、发行登记、测试名与宿主证据。

### 5.5 A2V 默认提示词

场景：用户选择 **LTX 2.5 音频生视频**（`local.bgx.ltx25/a2v`），提供首帧人物图和已有语音。工作台在提示词为空时自动填入下面这段英文，用户可改后再提交。

#### 官方规则（引用，不是我们写的模板）

| 来源 | 与本模板相关的官方说法 |
|---|---|
| [Prompting Guide](https://docs.ltx.io/open-source-model/usage-guides/prompting-guide) | 用现在时、连贯段落（约 4–8 句）写清镜头、动作、镜头运动；动作用动词，不要只写外貌。近景需要更多动作细节。情感用可见的身体线索，不要只用抽象形容词。镜头术语包含 **Static frame**、**Continuous shot**。指南写明：若希望一段对白表演保持在同一构图里，使用 **single continuous take**；从首帧做 image-to-video 时，除非有意切走，否则也优先单镜头。 |
| 同上 · Dub-It 专节 | 台词模板 `[Speaker] is speaking … saying: "…"` **仅适用于 LTX-2.3 Dub-It**（按提示词替换已有视频里的对白）。本包 A2V 不得套用该模板，也不在默认词里编造引号台词。 |
| [Audio-to-Video](https://docs.ltx.io/open-source-model/usage-guides/audio-to-video/) | 「音频驱动节奏与运动，提示词提供视觉内容。」可选首帧只设定 opening shot。输出附带**原始音频、不重新解码生成声音**。提示词不要去描写一段新的配乐或另写要对口型的台词。 |
| [Image-to-Video](https://docs.ltx.io/open-source-model/usage-guides/image-to-video) | 已有首帧时，提示词写 **接下来发生什么**（动作、镜头），因为模型已经从图像知道外观。官方举例用了 “The woman…” 和背景钢琴，那是 I2V（会**同时生成音轨**）的示范，**不能原样当 A2V 默认词**，以免虚构性别服饰或诱发新配乐。 |

官方指南正文是英文，Lightricks 示例也是英文。本模板采用英文作为自动填入、提交给模型的正文；中文只作说明书，不自动填进提示词框。

#### 我们编写的通用模板（非官方原文，不保证精确口型）

写入 `properties.prompt.default` 的完整正文如下（一行连续段落，按字符原样进入 schema，不加书名号或注释）：

```text
The person shown in the first frame remains the same person and talks while looking toward the camera. Mouth movement, blinking, and small natural shifts in expression and head position follow the timing of the supplied speech. Face, hair, clothing, and background stay consistent with the first frame. This is a single continuous take with a static camera, holding a medium close-up of the head and shoulders, with no pan, zoom, or cut. Lighting stays unchanged from the opening shot.
```

中文说明（仅 README，不进入 default 字段、不替代英文提交）：

> 首帧里的人保持同一身份，对着镜头说话。口部动作、眨眼和细微的表情、头部变化跟随**已提供语音**的节奏。面孔、发型、衣着和背景与首帧一致。单镜头、固定机位、中近景（头肩），不推拉摇移、不切换。光线与开场相同。

编写取舍：

- 用 “the person shown in the first frame” 锚定身份，不写年龄、性别、发色、服装或场景陈设。
- 写 talks / looking toward the camera / blinking / small natural shifts，对应官方「用动词写动作、用身体线索写表情」。
- “follow the timing of the supplied speech” 只说明跟随已有语音的节奏，不写引号台词。
- 不写 piano、ambience、new dialogue、soundtrack，避免诱发新音轨。
- 采用官方推荐的 single continuous take 与 static camera / medium close-up。
- **不是**官方逐字原文，也**不保证**音素级对口型。
- 首帧可选：不提供首帧时，用户应改写首句（README 写明；不另设第二条默认词，H24）。

#### 现有自动填入链路（复用，不另造）

1. 适配器在 A2V 的 input schema 声明 `properties.prompt`（string）及 `default`。
2. `capabilities()` 把 schema 全文（含 default）做 digest 放进 `capabilityContracts[].schemas` / `operations[].inputSchema`（ltx23 `lib.rs:75-77,116-135`）。manifest 不增字段。
3. 宿主投影为 `AdapterV2CapabilityEntry`，用户在工作台选中 `ltx25-a2v`。
4. `FcVideoWorkbenchModal.tsx:867-870` 以当前操作 descriptor 调 `useAdapterPromptDefault`。
5. `useAdapterPromptDefault.ts:15-22`：default 为非空字符串、工作台打开且未 loading、本次会话该 `scope + selection` 未初始化过，才调 `applyToEmptyPrompt`。
6. `useFcWorkbenchPromptBinding.ts:188-194` `applyDefaultPrompt`：已绑定节点、非输入法组合、草稿 trim 后为空时才 `setPrompt`。

沿用 2026-11-15 已验收行为：初次选择且为空才填；可手改；执行器与 submit 不补 default；同会话清空后不回填，重开空白草稿可再初始化；切换操作时已有文字保留；升级不回写历史节点；无 default 的操作保持空白。现行代码与此不符时以主仓代码为准更新本 PLAN，不改宿主策略。

# 20261115 图片与视频超分工作台发现

症状：图片超分和视频超分以前能在比格熊 AI Story 的超分工作台下拉里选到，现在看不到。云端没有用户运行日志，不能把复现猜测写成根因。下面的结论来自当前两边源码和发行声明。

## 期望

安装当前正式包后，图片超分与视频超分都以当前 SDK 的 `transportSlot`（`imageUpscale` / `videoUpscale`）被宿主发现，出现在对应超分工作台下拉，而不是写死选项。参数仍按各操作的输入 schema 过滤。提交、查询、取消声明和结果取回走同一条已安装包，不在失败后换原生通道。升级旧包后，下拉和任务引用的是该包声明的操作，不再依赖一份已经对不上的生图映射。

## 已证实根因

1. 图片包 `local.bgx.seedvr2-image` 1.0.3 的能力合同在 `packages/workflow-adapters/seedvr2-image/src/lib.rs` 的 `capabilities()`：`capabilityKey` 为 `local.bgx.seedvr2-image/upscale`，`transportSlot` 为 `imageUpscale`。这是 SDK schema 允许的命名空间键加已有传输槽，不是非法声明。
2. 宿主下拉不读这个传输槽。图片工作台 `ImageUpscaleWorkbenchHost` 只调用 `listImageUpscaleServiceOptions`，它只保留工作流绑定里 `capability === "imageUpscale"` 且 `registered` 的行。视频工作台 `listVideoUpscaleServiceOptions` 再要求 `capabilitySummary.postprocessChannel` 等于当前通道。
3. 已安装目录投影把直接模型行限定为标准键。`installed_image::supported` 要求 `capabilityKey == "image.generate"` 且带 `prompt`；`installed_video::supported` 要求 `video.generate`。超分包因此 `image_model_ids` / `video_model_ids` 为空，不会像生图/生视频适配器那样安装后出现。
4. 唯一还能登记进下拉的路径是安装完成时的 `register_workflow`。它要求已导入工作流的摘要等于 `workflow-templates.json`，并且 `binding_service::set_with_repo` 先调用 `image_adapter::generation_ready`。该函数对非 `image.generate` / `video.generate` 关联落到 `published_ready`，要求生图映射合同 `Ready` 且没有歧义。SeedVR2 超分图不是生图映射；认证矩阵对这类原件把 `mapping_ready` 当成可选。映射未就绪时登记失败，下拉保持空白。安装 ZIP 只有模板摘要，不自动导入工作流原件，所以新安装也不会自己出现选项。
5. 本适配器仓没有视频超分包。宿主 `ComfyUI-API/SeedVR2/video_seedvr2_hd_upscale.json` 只是原生工作流。视频下拉同样依赖上面的登记，且 `video_upscale` 没有 v2 执行分支，`providers::submit_channel` 的 SeedVR2 通道直接进 `seedvr2_comfy`。
6. 无运行日志。未在本环境启动 Windows 宿主、GPU 或 ComfyUI，不能把真实超分成功写成已验。

## 假设（实施时用测试闭合，不单独当根因）

已导入但映射未就绪的 SeedVR2 工作流，会被 `generation_ready` 拒绝登记。直接按传输槽列出已安装操作后，即使没有工作流库条目，下拉也能看到该操作。

## SDK 与旧包

保留 SDK。当前 `contract/v2` 与各包 vendor SDK 已经有 `imageUpscale` / `videoUpscale` 传输槽，`capabilityKey` 允许命名空间字符串。图片 1.0.3 的声明已经合法，不升 SDK、不改图片包版本、不覆盖 1.0.3 字节。视频包是新 pluginId `local.bgx.seedvr2-video`，首版 `1.0.0`，不占用图片包版本。未编出 wasm 之前不写入 `release/current.json`，也不把源码目录称为可下载安装包。旧工作流绑定仍保留；同一 plugin 已经通过工作流绑定出现时，不再追加第二条已安装行。

## 正常与失败

正常：已安装且 `transportSlot` 为 `imageUpscale` 的操作出现在图片超分下拉；`videoUpscale` 出现在视频超分的 SeedVR2 通道。模型 id 为 `installed-upscale:{pluginId}@{version}#{operationId}@{operationVersion}`。提交使用该包的能力键、操作和宿主配置里的网络源，查询沿原 vendorTaskId，结果按操作输出槽取回。包声明 `cancellation: unsupported` 时不提供取消。

失败：目录读取失败要显示错误，不能当成“没有适配器”。多个 Comfy 源匹配时不挑选。传输槽不是对应超分槽的包不进入该下拉。直接 id 不调用 `freeze_service`，避免把“不是 custom: 工作流”报成选择失败。没有对应安装包时提交失败，不回退到原生 SeedVR2 图。

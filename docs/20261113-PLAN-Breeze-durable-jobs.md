# Breeze durable submission and restart recovery

Scope: `packages/tts-adapters/breeze`, package `local.tts.breeze` 1.0.1. The upstream runtime remains 1.0.2. The previous 1.0.0-d synchronous package and its historical checkpoints remain readable and are never rewritten as a newer contract.

Observed gap: synchronous HTTP returns only an in-memory WAV; the adapter does not transmit its SDK request ID. The service's request status map is volatile and cannot return media. Host exit kills owned CLI and companion process trees. A submitted SDK checkpoint can therefore remain acceptance_unknown with no vendor task identity. Query and automatic resubmission are correctly refused, but there is no recovery of the interrupted cue.

Atomic implementation:

1. `companion/durable_jobs.py`: one process-owned persistent store, stable store identity, requestId/requestDigest identity, atomic receipt and WAV publication, same-ID acceptance deduplication. Resolve and submit use the same lock; a negative resolution first commits a permanent tombstone so a late submit cannot create work. Interrupted running jobs become an explicit failed terminal after the previous process owner is gone; no invisible new inference. Clone reference audio is copied before acceptance and its identity frozen. File IO/inference stays outside SQLite transactions.
2. `companion/sidecar_server.py`: standard job submit/status/audio/cancel/resolve endpoints over the same existing runtime and inference lock; old synchronous endpoint remains only for the installed historical package. Cancellation of an active model is observed until the worker actually completes. No false idle.
3. `adapter/src/lib.rs`, `capabilities.json`, `Cargo.toml`: standard SDK async submit/query/cancel, original three speech modes and parameter audit preserved. Submit reads the original SDK checkpoint identity. Unknown acceptance uses the public reconciliation capability being implemented in the SDK, not a host vendor special case or a second protocol. A synchronous old checkpoint cannot gain this capability retrospectively.
4. `tests/` and `build-package.py`: behavior tests for concurrent dedupe, changed input rejection, tombstone vs late submit, terminal output hash, reference snapshot, cancellation and restart. Build the new WASM with the latest synchronized sibling SDK. Keep the application build already in progress frozen.
5. Produce an immutable install ZIP with package/companion/LICENSE/SHA, install through the formal application owner with current-selection migration and historical task preservation, then perform controlled original-host-loss and same-request recovery. Publish source and complete downloadable bytes; download the remote artifact again and verify the digest before marking it distributed.

Self-review: no original user database or running hour job is touched. Model files and local recordings are not published. No 404 is treated as proof of non-acceptance; no timeout is treated as a stopped model. New attempt after confirmed failure is explicit, and unknown legacy tasks remain unknown. SDK/host reconciliation is owned by the parallel common owner; this package waits for that contract before claiming support or release.

Implementation evidence: Python durable service tests 7/7 and native Rust adapter tests 2/2 pass. The protocol-02 candidate passes the current SDK CLI real WASM capabilities/probe check; it is not a released package and records the SDK dirty source state. Package-local LF rules keep companion inventory bytes stable across Windows checkouts. Root has staged this complete candidate through the production managed-speech staging script into isolated logs only. Native model, application upgrade, public artifact and remote restore acceptance remain pending.

Cancellation is best effort: queued jobs become cancelled without execution; running jobs only record cancellation and retain the actual succeeded/failed terminal result. The host waits for this terminal before releasing its active lease; user cancellation does not destroy a successfully computed result.
